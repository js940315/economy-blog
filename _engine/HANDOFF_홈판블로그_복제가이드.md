## 1. 이 시스템이 하는 일 (한 줄)

매일 새벽 클라우드 루틴이 뉴스(RSS)를 읽어 **관점이 담긴 포스팅 + 이미지 5장**을 만들어 저장소 `output/`에 커밋·푸시한다. 사용자는 GitHub Desktop으로 받아 **네이버 블로그에 복붙 발행**한다.
> 네이버는 API 자동 발행을 막으므로 **"복붙 직전까지"가 자동화 범위**다. 이게 이 시스템의 설계 전제.

승부처는 **네이버 홈판(모바일 홈 노출)**. 조회수보다 **관점·반응(공감·댓글·공유·체류)**으로 이긴다.

## 2. 홈판 블로그 운영 철학 (주제 불문 동일 — 절대 원칙)

**네이버 홈판은 정보 경쟁이 아니라 관점 경쟁이다.**
독자가 전문 매체 대신 이 블로그를 보는 이유는 정보를 더 줘서가 아니라 **핵심을 씹어서 관점과 함께 정리해주기 때문**. 정보 나열 = 뉴스/보도자료 요약 = 실패한 포스팅.

모든 원문은 아래 셋 중 **하나 이상**을 더해 재구성한다. 셋 다 없으면 출력 무효·재작성:
1. 이 숫자·사건이 **독자 삶에** 실제로 어떤 의미인지 해석
2. 남들이 안 짚는 **각도**(원인의 원인, 숨은 이해관계자, 시차 효과, 경쟁 비교)
3. **조건부 판단**("~라면 ~할 가능성" 같은 편집자의 시각)

**EEAT를 구조적으로 심는다:** 경험("자료를 보니 저도 ~인 줄 알았는데" — 겪지 않은 걸 지어내진 않음) / 전문성(수치를 던지고 "이렇게 읽어야 한다"까지) / 권위(수치 출처 기관 명시) / 신뢰(불확실한 건 단정 말고 조건부).

## 3. 화자 페르소나 & 톤 (v2/v3 — 캐릭터 블로그)

중립 정보전달자는 널렸다. 이 블로그는 **"개미(소비자) 편에서 관점을 던지는 유일한 목소리"**를 지향한다.

- **화자**: 40대 직장인 1인칭. 큰돈 벌어본 적 없고 여러 번 물려봤지만 귀동냥 많고 결국 잘 되겠다는 열정. 타겟 독자 **40~50대**, 친밀·공감형.
- **셀프디스는 문, 분석은 방**: 손실·과거 얘기는 자조("나도 물렸다")로, 관점·해석은 자신감 있게 단정.
- ⛔ **없는 개인 수익률·손실액·체험을 지어내지 않는다.** "그 입장이면 다 아는 심정" 수준의 보편 공감까지만.
- **편·빌런**: 언제나 소비자 편. 분노·비판은 **빌런(구조·세력)에게만**, 독자·실존 개인에겐 절대 금지(명예훼손 금지). 공인의 공적 활동 비판도 사실 기반·조건부로만.
  - (경제 예시) 주식=외인·기관·세력 / 코인=고래·거래소·김프 / 부동산=정책·투기꾼 / 예적금·노후=은행·보험사 / 지원금=정부 생색·사각지대. → **자동차/건강은 이 "빌런 지도"를 주제에 맞게 새로 짠다**(예: 자동차=제조사 마케팅·리콜 은폐·중고차 허위매물 / 건강=과대광고·정보 비대칭).
- **감정 로테이션(양산형 회피)**: 매일 같은 세기면 식상해진다.
  - 기본(매일): 손실회피+연민+관점 (진라면~신라면 강도)
  - 스파이크(주 1~2회, **방탄 데이터가 딱 맞을 때만**): 계급·서열 낙인 (불닭 강도)
  - 가끔: 정보 정공법 / 셀프디스 공감
  - 기사 JSON의 `tone` 필드로 그날 톤 지정(class_spike / loss_aversion / self_deprecating 등).
- **말투**: 본문 몸통은 **존댓말 장문**(SEO·중년 신뢰용, 문장당 60자 내외, 문단 2~3문장). 첫 훅·소제목·콜아웃(💡)에서만 스레드식 구어로 스파이크. 본문 전체를 반말 단문으로 바꾸는 건 저품질이라 금지.

## 4. 제목 (홈판 화력 최대 — 근거는 100% 사실)

- **태도 단정형**으로 끝낸다("~입니다/~하세요/~밖에 없다"). "~일까요?" 질문형으로 도망가지 않는다.
- **앞 20자 안에 핵심 완결**(목록에서 잘려도 의미 통하게). 숫자·고유명사 포함. 2인칭 호명("당신/~라면").
- **사회통념 비트는 반전형** 우선("당연히 오를 줄 알았는데 되레 떨어진", "역대 스펙인데 예약 저조한 이유").
- 개인 실명 대신 **기관·브랜드·모델명**으로 후킹.
- ⛔ 금지: 근거 없는 가격/출시일 단정("OO원 간다"), 미확정 루머 단정, 매수·매도(구매) 암시, 사실 왜곡.
- (v2 공식) [키워드 앞쪽] + [감정 훅] + [뒤 여운]. 가격 단정 예측은 **관점으로 리프레임**.

## 5. ⭐ 썸네일 = 홈판 클릭률을 결정하는 단 하나의 요소 (가장 중요)

목록에서 스크롤하는 사람에게 주어지는 시간은 **1초**. 사진은 분위기만, **정보는 100% 텍스트**가 전달.
> images 배열의 **1번**은 반드시 홈판 대표 썸네일이다. **절대 데이터 카드로 만들지 않는다.**

**형식(예외 없음):** 정확히 **2줄**, 한 줄 **8~12자**(13자↑ 모바일서 작아짐), 합 16~24자.

**3초 판정 세트 — 아래 셋 중 최소 2개 필수:**
1. **시간 앵커**: 오늘/내일/이번주/다음달/내년부터 → "지금 봐야 할 이유"
2. **구체 숫자**: 150만원/41%/1424원 → 검증 가능해 보여 신뢰
3. **고유명사**: 하이닉스/코스피/(자동차면)아이오닉/(건강이면 특정 성분·질환) → "내 얘긴지" 즉시 판정

**문장을 끝내지 않는다(궁금증 갭)**: ~인 이유 / ~변수는 / ~라는데 / ~걱정 / ~가능성 / ~할까. (다 말해버리면 클릭 이유 소멸)
**말투**: 스레드체 구어. **강조 단어(숫자·고유명사)는 `accent_words`로 넘겨 민트색** — 시선이 먼저 가 판정이 빨라진다.
**배경 매칭**: 카피와 배경이 같은 얘기를 해야 한다(하이닉스 폭락 카피에 항만 사진 = 아마추어). 못 맞추면 밝은 풍경 대신 **어두운 단색+큰 숫자** 또는 `dim` 올려서.

두 타입:
- **(A) 종목·지수 등락** → `stock_thumbnail` (사진 아님, 곤두박질/급등 **차트를 직접 그림**. logo/price/delta/down 지정. 한국식 색: 상승 빨강/하락 파랑).
- **(B) 그 외 전부** → `thumbnail` (사진 배경 + 2줄 카피 + 두꺼운 외곽선 + 민트 강조 + 브랜드 배지). `photo_category`로 카테고리만 주면 엔진이 사진 자동 선택.

## 6. 본문 구조 · 반응 장치 · 가독성 (모바일 절대 규칙)

**도입부(3문장 이내):** ①제목 주장을 뒷받침하는 **구체 근거(수치)를 즉시** → ②"낚시 아니네" 판정 → ③그다음 궁금증으로 본문 연결. (근거 없이 자극만 = 낚시 인식·이탈)

**본문 4챕터(공백 제외 1,400~1,600자):** 발단·현황 / **원인 분석(가장 길고 구체적, 중심)** / 파장·이해관계자(누가 웃고 우는지) / 전망·시사점(독자가 챙길 점). 4챕터 어딘가 **"관통하는 해석 한 문장"** 명시.

**반응 4장치(글당 3~5개, 남용 금지):**
1. `📌 소제목` — 각 챕터. **궁금증형**("왜 웃을 수 없을까" O / "실적 요약" X). 빌더가 밑에 구분선 `━×19` 자동.
2. `💡 핵심 한 입` — 어려운 내용 뒤 1~2개. "쉽게 말하면 ~". (스캔하다 이것만 봐도 이해 → 체류↑)
3. **여운형 질문** — **글 맨 끝**(정리 다음, 면책 앞). 독자 자신 상황 떠올리는 열린 질문. `closing_question` 필드.
4. `💡 관점 한 문장` — 마지막 챕터, 여운 질문 앞. "이거 맞말이네" 싶은 한 줄. (공유↑)
> ⛔ **'댓글'이라는 단어 자체 금지, 구걸 금지.** 반응은 공감·자기대입으로 저절로 나오게.

**⛔ 마크다운 절대 금지**: 네이버는 마크다운을 해석 안 함. `**`,`##`,`- `,`` ` `` 쓰면 화면에 기호가 그대로 노출 → "AI 글" 인식·즉시 이탈. **볼드(▶) 마킹도 폐기**(네이버 미적용). 강조는 이모지+카드가 담당.

**가독성(내용보다 우선):**
- ⛔ **문장 중간 줄바꿈 금지.** `body_paragraphs`의 각 원소 = **문장 하나**. 빌더가 2~3문장을 한 문단으로 묶고 110자 넘으면 문장 경계에서 빈 줄. (네이버가 화면 폭에 맞춰 감싸므로 하드 줄바꿈은 어색하게 끊김)
- 한 문장 60자 이내. 문단 명시 구분은 배열에 `⠀⠀⠀`(점자 빈칸 3개) 원소 — 일반 공백/빈 문자열은 복붙 때 사라짐.
- 어미를 "~다."로만 끝내지 말고 구어체 섞기(~되었구요/~거든요/~거죠/~참 많으시죠?). 단 수치 첫 제시·챕터 첫 문장은 단정형(~습니다) 유지.

**마무리 고정 섹션(문구 변형 금지):** `📝 한눈에 보는 경제 노트`(주제명에 맞게 "~ 노트") → 조건부 시각으로 마감 → **여운형 질문** → **면책 한 줄**.
- 투자성 카테고리 면책: `※ 본 게시글은 투자 권유가 아니며, 투자 판단과 책임은 본인에게 있습니다.`
- (자동차/건강은 성격에 맞는 안내문구로 교체 — 예: 자동차 "실제 가격·출시일·사양은 제조사 공식 발표를 다시 확인해주세요." / 건강 "건강 관련 판단은 전문의 상담을 우선하세요.")

**해시태그 8개:** 1~6 고정 매핑(이슈명 / 이슈+수치 / 이슈+제도·모델명 / 핵심키워드 / 관련 기관·브랜드 / 관련 제도·법령) + 7~8 카테고리 풀에서 동적 선택. `#경제 #뉴스` 같은 광범위 태그 금지.

**출력 직전 9점 자체 점검:** ①4줄 넘는 문단 없나 ②문단 사이 빈 줄 다 있나 ③제목 단정형인가 ④도입부에 근거 있나 ⑤관점 문장 있나 ⑥분량 1,400~1,600자인가 ⑦근거 없는 가격/출시 예측 없나 ⑧유사문서 아닌가 ⑨소제목 형식 맞나 — 하나라도 실패면 재작성.

## 7. 이미지 시스템 (v3 — 5장 구성 + 프리미엄 사진 + 자동선택 엔진)

**5장 구성(v1의 4장에서 "실사 이미지" 1장 추가):**
1. **썸네일** — `thumbnail`/`stock_thumbnail`만(5절, 데이터카드 금지).
2. **실사 카드(`photo_card`)** — 주제 실사 사진 배경 + 헤드라인/숫자. `photo_category`로 카테고리 지정.
3~5. **데이터 카드 3장** — `bar_card`/`number_card`/`rank_card` 조합 → **마지막은 `summary_card`(정리 3줄)**.
> 빌더가 본문 글자수를 (이미지수+1)등분해 **마커를 자동 배치**한다. body에 수동으로 안 넣어도 됨(마지막 정리카드는 맨끝).

**카드 종류(`common_utils.py`):** thumbnail / stock_thumbnail / photo_card / bar_card / rank_card / number_card / summary_card. 전부 1080×1080, 남색 톤 통일, 하단 출처표기·배지 배경박스 없음, 1080px JPG q92.

**사진 자동선택 엔진(`photo_library.py`):** 기사 JSON에 `"photo_category": "부동산"`처럼 **카테고리만** 주면 `pick_photo(카테고리, 날짜, 순번)`이 그 카테고리 풀에서 **결정론적 순환 선택**(같은 입력이면 같은 결과, 날짜·순번 다르면 다른 사진). 최근 3장 회피(`state/photo_usage.json`)로 어제 쓴 사진 재등장 방지. `variation_seed`가 크롭 9방향·톤을 매번 살짝 다르게 → 같은 원본도 안 겹쳐 보임. 파일명 직접 지정(`"photo"`)도 호환.

**프리미엄 사진 소싱(Pexels/Unsplash/Pixabay):** `image_sourcing.py`의 `stock_photo_candidates()` + `build_stock_library.py`(카테고리 일괄) / `fetch_photo.py --stock`(단건). **키는 환경변수에서만**(`PEXELS_API_KEY`/`UNSPLASH_ACCESS_KEY`/`PIXABAY_API_KEY`) — 코드·커밋에 값 절대 금지. 세 API 모두 워터마크 없음+무료 상업 재게시 허용. 실제 짧은 변 ≥1120px만 채택→정사각 1400px(시리즈 톤/비네트)로 저장. **리사이즈본만 커밋**(대용량 원본 금지). 출처/촬영자/라이선스는 `assets/photos/index.json`에 기록.
> 소싱 후 **반드시 몽타주로 육안검수** → 주제 부적합/타 브랜드 오인 사진 제거. `.gitignore`가 `assets/photos/*`를 무시하므로 확정 사진만 `git add -f`.

**라이브러리 확충(반복·식상함 방지):** 카테고리당 5~6장 이상 쌓아두고 순환. 종목 기사는 `stock_thumbnail`(매번 다른 종목·가격·차트라 안 겹침) 비중을 늘린다.

## 8. 기술 파이프라인 & 빌드

**핵심 파일(`_engine/`):**
| 파일 | 역할 |
|---|---|
| `build_posts.py` | 기사 JSON → `output/{날짜}/{순번}/` (본문+이미지). **핵심** |
| `build_samples.py` | 샘플 전용 빌더(`output/samples/`에만 씀) |
| `common_utils.py` | 카드 SVG 빌더 + `convert_svg_to_png`(헤드리스 브라우저) |
| `photo_library.py` | 사진 순환 선택 + 변주 엔진 |
| `image_sourcing.py` | 사진 소싱(스톡 3API + Wikimedia/Openverse) |
| `build_stock_library.py` / `fetch_photo.py` | 라이브러리 구축 CLI |
| `fetch_logo/portrait.py`, `build_ticker_library.py` | 로고·인물·종목 자산 수집 |
| `PROMPT_V1.md` | 기사 생성 규칙(운영법 원전) |

**빌드(반드시 저장소 루트에서):**
```bash
python _engine/build_posts.py _engine/articles.json 0802
```
→ `output/0802/{순번}/`에 `0번 본문.txt` + `1~5번 사진.jpg`, `build_report.json`에 검증 결과(problems 0이어야 정상).

**8-1. 안정성/성능 (2026-08-02 하드닝):**
- 렌더는 이미지 1장마다 헤드리스 브라우저를 콜드스타트 → **동시 실행 수 = 순간 메모리**. 환경변수 **`RENDER_CONCURRENCY`**(기본 3)로 조절. 안정적 클라우드는 8, **저사양·불안정 PC는 1~2**.
- 상태/인덱스 JSON은 **원자적 쓰기**(tmp+os.replace+fsync) + **손상 시 자가복구**(`_load_json_safe`) → 쓰는 중 크래시해도 `photo_usage.json`/`index.json`이 0바이트로 깨지지 않음.

**8-2. 자동화 루틴(claude.ai 스케줄):** 매일 06:00 KST에 RSS 읽기 → 중복 회피(`state/seen_articles.json`, 최근 3일) → 기사 JSON 생성 → `build_posts` → `output/` 커밋·푸시. 사용자는 GitHub Desktop Fetch → 로컬 폴더에서 네이버 복붙.
> ⚠️ RemoteTrigger 부분 업데이트가 sources/프롬프트를 지운 적 있음 → update 시 전체 유지.

**8-3. ⚠️ `PROMPT_AUTO_V1.md`는 구버전:** 경제 v1 시절에 만들어져 현재 v3와 어긋난다. 자동차 방에서 **아래를 v3 기준으로 갱신**해야 함:
- 소제목 `📌 **볼드**` → **볼드 제거**(마크다운 금지, 구분선은 빌더 자동).
- "본문에 마커 수동 삽입" → **빌더 자동 배치**(수동 불필요).
- 4장(썸네일+카드3) → **5장(썸네일+`photo_card`+카드3)**, `photo_category` 자동선택 반영.
- `closing_question`(여운형 질문) 필드, v2 페르소나·감정 로테이션 절 추가.
- 가독성 "45자·3줄" → v1의 "문장 60자·문단 110자, 문장 중간 줄바꿈 금지"로 통일.
- 자동차 고유 안전장치는 유지: **안 타본 차를 "타보니"로 쓰지 않기**(반드시 3인칭 인용), 출시일·가격·리콜은 공식 발표 근거만.

## 9. 새 주제로 복제하는 법 (자동차·건강)

**엔진 코드(`_engine/*.py`)는 100% 재사용.** 주제별로 바꾸는 건 사실상 아래 5가지뿐:

1. **새 저장소**: `economy-blog`를 새 repo로 복제(예: `car-blog`, `health-blog`). Public 권장(링크 공유 발행).
2. **⚠️ Claude GitHub App을 그 repo에 "설치"**: github.com/apps/claude/installations/new 에서 새 repo 선택(권한에 code read/write). **인증만으론 push 403**("Resource not accessible by integration"). repo마다 개별 설치 필요. (자세히는 `SYSTEM_STATE.md` / 메모리 `economy-blog-github-push`)
3. **브랜드명**: `build_posts.py`의 기본값(brand/tagline)과 배지 문구 교체.
4. **카테고리 & 사진 검색어**:
   - `PROMPT`의 카테고리 7종을 주제에 맞게(자동차: 신차·출시/전기차·친환경/자동차산업·수출/리콜·안전·정책/모터스포츠/중고차·시장동향/브랜드·기업이슈 — 초안 있음).
   - `build_stock_library.py`의 `TOPICS`/`COMPANIES` 검색어를 주제 카테고리에 맞춰 새로 작성 → 카테고리당 5~6장 소싱 → 육안검수 → `git add -f`.
5. **주제 규칙(PROMPT) & RSS 소스**: `PROMPT_주제.md`를 위 8-3대로 v3 기준으로 작성. 루틴 프롬프트의 RSS 소스를 그 주제 매체로 교체. 중복 파일은 `state/seen_articles_주제.json`.

**바꾸지 않는 것(그대로 복사):** 홈판 운영 철학(2절)·페르소나 골격(3절)·제목/썸네일/본문/반응장치/가독성 규칙(4~6절)·이미지 5장 구성과 엔진(7절)·빌드/안정성(8절). **"홈판용 블로그 운영법"은 주제 불문 동일하다** — 이게 이 시스템의 자산이다.

**주제 분리 원칙**: 주제마다 저장소를 분리해야 유사문서(같은 공장 티)를 피한다.

## 10. 함정·주의점 모음 (실측으로 확정된 것 — 꼭 읽기)

- **Pexels 403 = 키 문제 아님**: Cloudflare가 봇 UA(`Python-urllib`/커스텀)를 error 1010으로 차단. **브라우저 UA(STOCK_UA)** 필요. (코드에 이미 반영)
- **Pixabay 무료 API는 긴 변 1280px 상한** → 정사각 1400 카드에 거의 기여 못 함. 실제 소싱 소스는 **Pexels+Unsplash**.
- **스톡에는 브랜드 특정 사진(삼성 사옥, 특정 차종 실물)이 없다** → 일반 스톡은 "주제성" 이미지만. 실제 로고·사옥·차량·인물은 **Wikimedia/뉴스룸**(`fetch_logo/portrait.py`, `image_sourcing`의 commons 경로) 또는 `economy-image-sourcing` 스킬. 기업 카테고리 사진은 index.json에 "브랜드 미검증" 명기.
- **Openverse 검색어는 1~2단어로 짧게**(3단어↑면 0건 잦음). Wikimedia 임의폭 썸네일 렌더가 일부 파일서 HTTP 400 → 원본 URL 폴백 있음.
- **저작권/초상권은 "무조건 안 된다"가 아니라 라이선스로 판단**(PD/CC/KOGL 등 재게시 가능한 것만, 반드시 육안검수). 뉴스 보도사진 무단 전재는 금지.
- **키는 환경변수에서만**. 코드/커밋에 값 절대 금지. `.gitignore`에 키 파일·`assets/photos/*`·`*.tmp` 포함 확인.
- **저사양/불안정 PC**: 무거운 빌드가 커널 크래시(MEMORY_MANAGEMENT 블루스크린)의 방아쇠가 될 수 있음(2026-08-02 로컬 4회). `RENDER_CONCURRENCY=1~2`로 낮추고, 근본은 RAM/디스크 점검(mdsched/chkdsk). OneDrive가 파일을 NUL로 손상시킨 사례도 있어 원자적 쓰기 도입됨.
- **네이버 규칙**: 마크다운·볼드 금지, 문장 중간 줄바꿈 금지, 문단 구분은 `⠀⠀⠀`, '댓글' 단어 금지, images 1번은 반드시 썸네일(데이터카드 금지).
