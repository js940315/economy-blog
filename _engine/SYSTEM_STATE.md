## 확정된 규칙 (사용자 피드백으로 굳은 것 — 함부로 바꾸지 말 것)
- 문장 중간 줄바꿈 금지. 문단(2~3문장) = 한 줄, 네이버가 감쌈. 110자 넘으면 문장경계서 빈줄.
- 소제목 📌 밑에 구분선 ━×19 자동. 콜아웃 💡(핵심/관점)·👉는 독립문단.
- 여운형 질문은 글 맨끝(정리 다음, 면책 앞). '댓글' 단어 절대 금지, 구걸 금지.
- 면책 짧게: "※ 본 게시글은 투자 권유가 아니며, 투자 판단과 책임은 본인에게 있습니다."
- 이미지 4장은 빌더가 글자수 균등 배치 (body에 마커 안 넣어도 됨). 마지막은 정리카드=맨끝.
- ⭐ images 1번 = 반드시 '홈판 대표 썸네일'. 종목 등락=stock_thumbnail(곤두박질/급등 차트),
  그 외=thumbnail(사진배경+2줄 스레드체 카피+민트강조+경제비버 배지). 데이터카드로 만들지 말 것!
  2~4번만 bar/rank/summary/number/photo_card. (PROMPT_V1.md 7절 참고)
- 이미지 = 1080px JPG q92 (폴더 540KB). 종목기사 썸네일은 한국식 색(상승 빨강/하락 파랑).
- 볼드마킹(▶)은 폐기 (네이버 미적용). 강조는 이모지+카드가 담당.

## 이미지 소싱 한계 (실측 확정)
- Wikimedia Commons 직접 = 고해상 보장, 채택. Openverse = 축소본 많아 실측검증 필수.
- Unsplash/Freepik/Pexels = 차단(401/403). korea.kr = 720px 상한.
- 감정 스톡사진(슬픈 직장인 등) 무료로 거의 없음 → 종목은 차트 직접 생성, 생활감정은 사물 대체.
- 로고/인물은 상표·초상. 재게시 가능 라이선스(PD/CC/KOGL)만, 반드시 육안 검수.
- Openverse 검색어는 짧게(1~2단어)! 3단어 이상 조합하면 결과가 0건으로 잘리는 경우가 잦다
  (예: "bitcoin coin close up photo"=0건, "bitcoin coin"=정상). 안 나오면 단어 수부터 줄여본다.
- Wikimedia 썸네일 렌더(`wikimedia_thumb_url`, 임의 width)가 일부 파일에서 HTTP 400
  ("Use thumbnail sizes listed…")을 낸다 — 위키미디어가 임의 폭 렌더를 막기 시작한 파일들.
  `image_sourcing.py`의 `photo_candidates()`에 원본 URL 폴백을 넣어 고침(2026-08-02) —
  이미 원본이 크면(대부분 4000px+) 어차피 빌더가 1080px로 다시 줄이므로 무겁지 않다.
- `fetch_photo.py`의 성공 판정 버그도 같이 고침: "skipped"(축소본이라 스킵) 항목을
  파일이 저장된 것처럼 잘못 세던 것을 `"path" in r` 기준으로 수정(2026-08-02).

## 경제비버 v2 제작 스펙 (2026-08-02 확정 — 톤/페르소나 대개편, 테스트 진행 중)
v1(위 "확정된 규칙")은 중립적 정보전달자 톤이었다. v2는 여기서 한 걸음 더 나가
"개미 편에서 관점을 던지는" 캐릭터 블로그로 전환한다. 현재는 `output/samples/0802_v2/`에서
샘플로만 검증 중 — 실제 발행(`output/{MMDD}/`)과 자동화 루틴 프롬프트는 아직 v1 그대로다.
v2를 정식 채택하면 루틴 프롬프트·PROMPT_V1.md를 v2 기준으로 다시 정리해야 한다.

1. **노스스타**: 중립 정보전달자는 이미 널렸다. 경제비버는 개미 편에서 관점을 던지는
   유일한 목소리를 지향한다. 정보 나열이 아니라 "이건 이렇게 봐야 한다"는 입장이 있어야 한다.
2. **페르소나(화자)**: 경제비버 = 40대 직장인, 국장에 여러 번 물린 개미. 큰돈 벌어본 적은
   없지만 귀동냥은 많고, 그래도 결국은 잘 되겠다는 열정이 있는 1인칭 캐릭터.
   - 타겟 독자: 40~50대 이상. 친밀감·공감형 어투.
   - 셀프디스는 문, 분석은 방: 손실·과거 베팅 얘기는 자조("나도 물렸다")로 풀고,
     관점·해석을 펼 때는 자신감 있게 단정한다.
   - 구체적인 개인 수익률·손실액을 지어내는 건 금지. "개미면 다 아는 심정" 수준의
     보편적 공감까지만 — 없는 개인 경험을 사실처럼 창작하지 않는다.
3. **편(便)과 빌런**: 경제비버는 언제나 개미 편이다. 분노와 비판은 빌런에게만 겨누고,
   독자나 실존 개인에게는 절대 겨누지 않는다(명예훼손 금지, 공인의 공적 활동 비판은
   기존 톤 규칙과 동일하게 사실 기반·조건부로만).
   - 주식 = 외국인·기관·세력
   - 코인 = 고래·거래소·김치프리미엄
   - 부동산 = 정책·투기꾼
   - 예적금/노후 = 은행·보험사
   - 지원금/정책 = 정부 생색내기·사각지대
4. **감정 로테이션**: 매일 같은 세기로 반복하면 충격이 인플레돼 식상해진다(양산형 회피).
   - 기본(매일): 손실회피 + 연민 + 관점. 강도는 "진라면~신라면" 정도.
   - 스파이크(주 1~2회, 또는 방탄 데이터가 딱 맞아떨어질 때만): 계급·서열 낙인,
     불닭 매운맛 강도.
   - 가끔: 정보 정공법 / 셀프디스 공감형.
5. **제목 공식**: [종목·검색키워드를 앞쪽에] + [감정 훅] + [개미 관점의 뒤 여운].
   가격을 단정 예측하는 표현("내일 X만원 아래로")은 금지 — 반드시 관점으로 리프레임한다
   (기존 "절대 금지" 규칙과 동일선상, 화력은 감정과 여운에서 낸다).
6. **계급/서열 시리즈(스파이크 전용)**: [커트라인 숫자] + [계급 낙인] + [인정하기 싫은 진실]
   구조. 자산/소득/주식/코인/부동산/노후/지원금 등 카테고리별로 만들 수 있다.
   - **방탄 데이터 원칙**: 커트라인 숫자는 반드시 통계청·KB금융·한국은행 같은 공신력 있는
     출처의 실제 통계를 근거로 한다 — 반박당해도 무너지지 않아야 스파이크 톤을 써도 안전하다.
   - 판단은 항상 집단(계층·구간) 단위로만 하고, 실존 개인을 특정해 서열을 매기지 않는다.
7. **말투**: 본문 몸통은 존댓말 장문(SEO·40~50대 신뢰용 문체, 기존 가독성 규칙 그대로
   문장당 60자 내외·문단 2~3문장). 첫 훅·소제목·콜아웃(💡 등)에서만 스레드식 구어로
   스파이크를 준다. 순수 스레드 단문 포맷을 본문 전체에 이식하는 건 저품질로 보여 금지.
8. **이미지 5장 구성** (v1의 4장에서 "실물 이미지" 1장이 추가됨):
   1. 썸네일 — thumbnail 또는 stock_thumbnail만(데이터카드 금지, v1 규칙 그대로).
      후킹 카피 2줄.
   2. 실물 이미지 — 실존 인물 사진, 또는 종목이면 로고·본사·현장 사진.
      저작권·초상권은 금지가 아니라 라이선스 기준으로 판단해서 실제로 소싱한다
      (`economy-image-sourcing` 스킬 / `_engine/fetch_photo.py`, `fetch_portrait.py`,
      `fetch_logo.py` 사용, `assets/photos|portraits|logos|tickers/index.json`에 기록).
   3~5. 카드 3장 — 데이터 카드(bar/number/rank 중 필요한 조합) → 마지막은 summary_card로
      정리. (v1 규칙 그대로 유지: 카드 출처표기 텍스트 없음, 배지 배경박스 없음,
      1080px JPG q92, 문단·구분선·콜아웃·여운형 질문·면책 규칙 유지.)
9. **네이버 홈판 레버**: 첫 3줄(더보기 접히기 전)에 훅을 배치. 마지막 여운형 질문은
   찬반이 갈릴 만한 질문으로 던져 댓글을 유도한다('댓글' 단어 자체는 여전히 금지).
   06:00 발행 유지, 매일 꾸준히 발행. 저품질 회피 = 제목은 맵게 쓰되 본문은 방탄
   데이터로 반드시 뒷받침한다(payoff 필수, 낚시성 이탈 방지 원칙은 v1과 동일).
10. **채널 분리 (기록만, 이번 생성물은 네이버 하이브리드용)**: 스레드는 진짜 반말 단문

## ✅ 썸네일 카피 가독성 — 해결 완료 (2026-08-03)
문제였던 것: 카피가 길면 폰트가 80px까지 깎여 모바일 홈판에서 안 읽힘.
확정 원칙: **"폰트를 줄이지 말고 줄을 늘려라."**

구현 = `common_utils.layout_thumb_copy(line1, line2)` → `(줄 리스트, 폰트크기)`
  1. 작성자가 끊어준 2줄이 86px(COPY_PREFER_FS) 이상이면 그대로 존중
  2. 안 되면 어절 단위로 2줄→3줄→(최후)4줄까지 늘리며 큰 폰트를 찾는다
     — 분할 우선순위: 폰트 크기 > 작성자가 끊은 자리 > 줄 길이 균형
  3. 폰트 하한 76px(COPY_MIN_FS) 절대 보장, 짧은 카피는 118px(COPY_MAX_FS) 초대형
실측 결과: 6~10자 → 118px / 11~12자 → 106~108px / 긴 카피 → 3줄 90px (2줄 80px 대비 크게 개선)

폭 추정(`_est_text_width`) 함정 2가지 — 실측으로 잡음, 건드릴 때 주의:
  - '%'는 좁은 기호가 아니라 사실상 전각(0.95). 좁게 잡으면 '41%는~'이 오른쪽으로 넘친다
  - 글자 외곽선(fs*0.17)이 좌우로 삐져나오므로 그 몫을 폭에 더해야 한다
프롬프트도 함께 조임: PROMPT_V1.md 3-1절·7절 → 한 줄 6~10자(최대 11자).
  "3줄 자동전환은 안전장치일 뿐, 길게 써도 되는 핑계가 아니다"까지 명시.
